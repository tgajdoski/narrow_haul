## Context (already built in another session)
- `test/autopilot/` is a headless autopilot that flies every level through the real
  game code (`flutter test test/autopilot --dart-define=STORE_CAPTURE=true`,
  optional `--dart-define=LEVELS=a,b`, `CLEAN=true`, `PROFILE=<name>`, `TRACE=<frames>`).
  - `harness.dart` boots `NarrowHaulGame` headless, steps it at 1/60 s, and feeds
    `rotateAxis/thrustHeld/fireHeld`.
  - `autopilot.dart` plans a route with `lib/game/level/cave/route_planner.dart`
    (`NavGrid`, clearance-weighted A*, `smoothPath`) and flies it with several
    `PilotProfile`s (careful/steady/brisk/racer). It keeps the best result per level.
  - `hazards.dart` predicts moving obstacles via `lib/game/level/cave/obstacle_paths.dart`.
- Per level it measures delivery, fuel left, time, stars, and which profiles succeed.

## Goal
1. **Difficulty report:** extend the autopilot run to export, per level, a difficulty score
   and a label: "3★ comfortable", "3★ tight", "3★ needs help", or "bot can't pass, needs
   human playtest". Base it on the 3★ fuel margin, the time margin, how many profiles
   succeed, and the time spent waiting at hazards. Write `build/autopilot_report.md`
   plus a machine-readable JSON.
2. **Route ghost for players:**
   - Export the best flight's ship trajectory (positions, every ~0.1 s, with timestamps,
     plus tow/attach markers) into a bundled asset, e.g. `assets/routes/<saveId>.json`,
     generated by an opt-in autopilot run. Don't replay inputs: obstacle timing and
     physics drift make an input replay unreliable. Show a path instead.
   - In-game: after **3 crashes in a row** on the same level (track it in
     `NarrowHaulGame`, reset on a delivery), offer a "Show route" button on the
     game-over overlay.
   - When enabled, draw the route as a dotted line in the world (priority between
     terrain and rope). Optionally add a translucent ghost ship moving along the
     timestamps from launch.
   - Decide whether using the ghost should affect stars (e.g. no 3★ while the guide is
     on, like `continuedThisRun`) and whether it should be a rewarded-ad placement
     (see Monetization in CLAUDE.md).
   - Persist "route unlocked" per level in `ProgressService`.
   - Optional "Watch a demo flight": play the recorded trajectory back
     kinematically (ship + pod positions over time, obstacles in sync from
     level load), so it looks like the bot flying but can't fail. No stars.
   - The bot already records its flight: `FlightResult.track` (`TrackPoint`:
     x, y, fuel burned, towing) every 0.1 s, so the export only has to
     serialize the best run's track.
3. Tests: route JSON loads for every level, the 3-crash counter logic works, and the
   overlay button only appears when a route exists.
