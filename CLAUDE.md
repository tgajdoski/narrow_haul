# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
flutter pub get          # Install dependencies
flutter run              # Run the game (use a landscape-capable device/simulator)
flutter test             # Run tests
flutter analyze          # Static analysis / linting
```

There is no Makefile or custom build script — all operations go through `flutter`.

## Architecture Overview

**Narrow Haul** is a 2D physics-based Flutter game. The tech stack is:
- **Flame v1.36.0** — game engine (component/system model)
- **Forge2D v0.19.2** — Box2D physics (via `flame_forge2d`)
- **tiled v0.11** — `.tmx` parsing for the tutorial levels (`TiledLevelLoader`, no Flame Tiled renderer)
- **shared_preferences** — persistence for progress, cosmetics, achievements

`Flame.images.prefix` is set to `'assets/'` in `main()`, so all image paths are relative to `assets/` (not the default `assets/images/`).

### Game Class (`lib/game/narrow_haul_game.dart`)

`NarrowHaulGame` extends `Forge2DGame`. It is the single master controller:
- Owns the `RunState` enum (`menu | playing | gameOver | won`) and drives all state transitions
- Holds references to the active `ShipBody`, `CargoBody`, `CargoAttachment`
- Manages level lifecycle: load → play → teardown (all level entities tracked in `_levelEntities` for bulk removal)
- Reads `rotateAxis` (−1.0 to 1.0) and `thrustHeld` (bool) from `HudTouchControls` each frame, then calls `ship.setInput(...)`
- Calculates stars (1/2/3 based on remaining fuel %), saves progress, fires achievement checks after win
- Hosts the daily challenge mode (`isChallengeMode`, `activeChallengeConfig`)

### Physics System (`lib/game/physics_constants.dart`)

- **Scale:** 32 px = 1 meter (`pixelsPerMeter`). Tiled tiles are 32 px.
- **Gravity:** `kGravityY = 1.375 m/s²` (debug builds use 70% of this via `kDebugReduceGravity`)
- **Collision bitmasks:** `categoryWall=0x0001`, `categoryShip=0x0002`, `categoryCargo=0x0004`, `categoryGoalCargo=0x0008`, `categoryGoalShip=0x0010`, `categoryHook=0x0020`. Hook sensor only collides with cargo; ship/cargo do not collide with each other directly (rope joint handles connection).
- **Tags** in `lib/game/tags.dart` are used in `beginContact` callbacks to identify collision partners.

### Rope/Tow System

Tow gear is chosen in the Garage (rope category) and is a real **sidegrade**, not just a colour. `RopeSpec` (pure Dart, `lib/game/ship/loadout.dart`, `kRopes` keyed by the cosmetic id, `ropeById`) sets hook reach, approach distance, an elastic one-sided spring (`stiffnessHz`, `dampingRatio`, `maxStretch`), `swingDamping`, `podMassAdd` (line weight added to the towed pod), and the tractor-beam fields. The stock `rope_cable` is exactly the original rigid tow (`test/loadout_test.dart`). The lineup is: Steel Winch Cable (stock), Tow Chain (swing damping, +35% pod weight), Long Line (rank, a little give and reach), Magnetic Grapple (`rope_energy`: grabs from a hover, springy), Shock Cord (`rope_neon`: very elastic) and Tractor Beam (`rope_tractor`, 500 coins). The game reads the equipped id (trial override included) at spawn and passes the spec down. Garage rope tiles show the blurb and `RopeStats` bars.

1. **`cargo_attachment.dart`** — monitors ship–cargo distance. Fades in the line at `rope.approachDistance`. Auto-attaches when the hook is within `hookRadius + cargo radius + rope.hookReach`, or when the ship centre is within `rope.attachCenterDistance`. With a beam it locks on within `beamRange` through clear line of sight (`hasLineOfSight`) and drops the pod when the beam breaks (`onBeamLost`, 0.6 s re-lock delay).
2. **`rope_physics_coupling.dart`** — creates the Forge2D joint. Uses `RopeJoint` for normal distances (≥ 0.12 m) or `DistanceJoint` for very short distances. Ship anchor = winch at `rearLocalY`; cargo anchor = cargo world centre. `maxLength` = distance at attach clamped to `levelData.ropeMaxLength`. An elastic rope makes that the rest length, puts the hard cap at `× (1 + maxStretch)`, and adds a one-sided spring force each frame (it pulls, never pushes). `swingDamping` damps the pod's swing relative to the ship. Both apply equal and opposite forces to ship and pod. `podMassAdd` scales the pod's fixture density while towed and restores it on removal. Hook reach is never below stock (`test/loadout_test.dart`), because a pod on a slope rolls away from a short hook (lava_06).
3. **`tractor_beam_coupling.dart`** — beam tow with no joint. A capped PD spring (cap `beamMaxAccel` × a standard pod's mass, so heavy pods lag) pulls the pod to `beamHoldLength` below the winch along local gravity, or the ship's down axis in zero-g. A far pod is reeled in at 1.6 m/s. The reaction goes on the ship, so the pod's weight still loads it. Drains `beamFuelFracPerSec` × tank per second. Breaks on > 0.25 s without line of sight, beyond 1.1 × range, or out of fuel.
4. **`rope_line.dart`** / **`tractor_beam_line.dart`** — visuals only. The rope is a Bézier sag that thins and brightens when stretched. The beam is a gradient cone with travelling rings, a pod halo, a flicker near the force cap, and a fizzle on break. Opacity is driven by `ropeRevealProgress`.

Autopilot: `--dart-define=ROPE=<id>` flies every level with that tow gear (set in `GameHarness.loadLevel`). With a beam, the bot plans the tow at the beam's hold length, not the lock-on distance. Planned next: winch in/out, release & re-hook, beam sounds, and ship Kits (Engine/Tank/Handling sidegrades).

### Level System

`LevelRegistry` (`lib/game/level/level_registry.dart`) is the authoritative list: 7 `WorldDef`s → 60 `LevelDef`s (flat index = play order). Two level kinds (sealed `LevelDef` in `level_def.dart`):

1. **`TmxLevelDef`** — the 10-level Tutorial world. `.tmx` files in `assets/tiles/` (level_01…level_10). `TiledLevelLoader` parses object layer "walls" (rectangles → static bodies) and "markers" (`ship`, `goal`, `cargo_zone`, optional `fuel` canisters with float property `amount`).
2. **`CaveLevelDef`** — 50 organic cave levels in 6 themed worlds (Alien/Mine/Ice/Lava/Orbit, 8 each; Redoubt, 5) plus a `rating_<ship>` type-rating level opening the Alien, Mine, Ice, Orbit and Redoubt worlds, defined as const `LevelSpec` data in `lib/game/level/specs/world_*.dart`. **No external editor** — hand-authored Dart data.

**Cave pipeline** (`lib/game/level/cave/`): `LevelSpec` (tunnels = Catmull-Rom splines with per-point half-widths, chambers = ellipses, anchors, obstacles, modifiers) → `cave_builder.dart` samples a signed distance field (smooth-min union, seeded fbm noise for the ant-nest look, noise fades near anchors) on a 0.1 m grid → marching squares → Chaikin + Douglas-Peucker → contour loops. Loops become one static body with `ChainShape.createLoop` fixtures (`CaveTerrain` component) and an even-odd filled `Path` for rendering. The theme's blurred edge glow is pre-rendered once per level into a small bitmap (16 px/m), not blurred every frame. Deterministic: noise seed is the spec's explicit `seed` int — levels are fixed, never random. Builder is pure Dart (headless-testable) and memoized per level id (cache cleared each load in debug for hot-reload authoring). At level load `prebuildCave(spec)` builds it on a background isolate (`Isolate.run`) so the UI never freezes; later `buildCave` calls hit the cache.

**Validation:** `test/cave_level_validation_test.dart` proves every cave level completable (anchor openness, BFS reachability with ship clearance, cargo rest-point approachability, obstacle sweeps clear of anchors, determinism, build-time budget). Authoring aid: `dart run tool/preview_levels.dart [id]` prints ASCII maps + issues. **Run this after any spec edit.** Common authoring gotcha: a cargo pocket must be a bowl — connect its tunnel at/above the pocket center, never as a slope under the cargo, or the cargo rolls out. **Delivery pads:** the builder lays a flat rock shelf (`_layPadShelf`, 1.5 m deep, pad width + 0.4 m each side) `kPadFloorDrop` (0.3 m) below every cave pad box and clears the box above it. The win sensors (`DualLandingZone`) reach `kPadSensorDrop` (0.45 m) below the box, so a ship or the tiny pod (r 0.093 m) resting on that floor counts (the validator's `pad not grounded`, and the `landing pads` test). Never put a pad straight above a shaft or the only way through: the shelf would plug it. Put it in a side lobe (lava_06, redoubt_04/05). Tutorial TMX goals are hover zones in the air, by design.

**Flight checks** (`analyzeFlight` in `level_validator.dart`): along the shortest 8-connected route spawn → cargo → goal, *lift* = loaded thrust accel ÷ strongest pull at the heaviest daily gravity (must be ≥ 2.0), and *fuel* = impulse floor ∫|pull + hull drag·v|/a_thrust dt at 2.5 m/s cruise × 1.3 overhead (must be ≤ 60% of tank). Clearance and both checks use the level's ship. The preview tool prints these per level and warns `⚠ 3★ tight` when the estimate exceeds the 3★ fuel budget. Fuel canisters within 1.2 m of that route are credited (capped by what's been burned by then). This is only a floor estimate — the autopilot below is the real check.

**Autopilot flight test** (`test/autopilot/`, tag `autopilot`, skipped in normal runs): `flutter test test/autopilot --run-skipped --dart-define=STORE_CAPTURE=true [--dart-define=LEVELS=a,b]` flies every level headless through the real `NarrowHaulGame` (fixed 1/60 s steps, same `rotateAxis/thrustHeld/fireHeld` inputs as the HUD) and writes `build/autopilot_report.md` + `.json`: bot fuel/time per level (hazards on, and a clean run with `debugSkipHazards`), the expected player cost (bot × `kHumanFuelFactor`/`kHumanTimeFactor` = 1.3) against the 3★ thresholds, and suggested fuel canisters for tight levels. It fails unless every level passes or is in `kNeedsHumanPlaytest`. Routes come from `route_planner.dart` (`NavGrid`: clearance distance map, clearance-weighted A*; turret domes/reactors are solid). The bot (`autopilot.dart`) flies four `PilotProfile`s and keeps the best; moving obstacles are predicted via `obstacle_paths.dart` and crossed by deterministic trial and error over hold times (`_tactics`), turrets are sniped from hidden firing points (reactor first), or in *assault* mode shot from inside their view (turrets covering the tow route are cleared first, on the way to the pod), or dodged; enemy shells are dodged reactively. Each flight records time spent in a live turret's view and kills. Debug knobs: `PROFILE=`, `TRACE=<frames>`, `NOSEARCH=true`, `DODGE=true` / `ASSAULT=true` (with NOSEARCH), `CLEAN=true`. The report also ranks levels by a difficulty score (0–100: fuel margin, time margin, profiles that failed, time spent waiting at hazards; pure `test/autopilot/difficulty.dart`, thresholds `kTight*`) with a label: 3★ comfortable / 3★ tight / 3★ needs help / bot can't pass. `EXPORT_ROUTES=true` writes each delivered level's flight (most careful 3★ profile; on armed levels the 3★ flight with the most turret kills, then the least time under fire) to `assets/routes/<saveId>.json` for the route guide. Calibrate the 1.3 margin with real flights: debug builds print `RUN <id> fuelLeft=… time=… stars=…` on every delivery.

**Route guide & demo flight** (`lib/game/route/`, `components/route_guide.dart`, `ui/route_guide_overlays.dart`): `FlightRecorder` records every flight (ship pose, pod, tow/thrust, shots) every 0.1 s on the *level-load* clock, so a replay stays in step with obstacles; delivery leaves it in `lastFlightRoute` (the autopilot exports this). `RouteRepository` loads the bundled `assets/routes/<saveId>.json` (ignored if recorded with another ship, never in a daily). After 3 crashes in a row on a level (`CrashStreak`, reset by a delivery), or once a level's route is unlocked (`route_unlocked_<id>`, free, no ad), the game-over screen offers *Show route* (dotted `RouteGuideLine` + translucent `RouteGhost` timed from launch; pause-menu toggle; a guided flight is capped at 2★ via `guidedThisRun`) and *Watch a demo* (`demoMode`: level reloaded with the engine paused, ship + pod kinematic along the recording, `CargoAttachment.scriptedTow` instead of a rope joint, turrets are live once the replay passes the recorded launch — their timing is seeded per turret and runs on the level-load clock, so they fire the shells the bot survived; a shell reaching the demo ship just vanishes, counted in `demoShellHits` — recorded shots are replayed as the very same shells — `FlightRoute.shotRays` stores each shot's muzzle and velocity — no meltdown, no stars/stats). On the guide line, dots a live turret covers (`Turret.covers`) are red, a crosshair with a dashed aim ray marks each recorded shot burst (`FlightRoute.fireMarks()`), a dashed ring marks where the flight held still ≥ 0.8 s, and the ghost shows a muzzle flash at shot times. `test/route_test.dart` checks every bundled route still starts on the spawn, hooks the pod, ends on the pad and stays out of rock, and that every level outside `kNeedsHumanPlaytest` (now empty) has one (60 routes, ~780 KB), and that each turret level's demo is never hit and its shot bursts knock something out — re-export a level (`LEVELS=<id> EXPORT_ROUTES=true`) after editing it.

**Theming:** `ThemeSpec` per world (`lib/game/level/theme_spec.dart`) — backdrop, rock palette, parallax tint/alphas, pad + UI accent colors, edge glow, decor tip color/density, `AmbientKind` particles. Applied in `_spawnLevel`. Optional art in `assets/themes/<id>/` (`rock.png`, `far/mid/near.png`, `decor.png` — spec in `assets/themes/README.md`) is loaded by `ThemeAssets`; every file falls back to the flat look (shared tinted parallax `assets/{far,mid,near}.webp`, solid rock, procedural spikes). Every world ships a `rock.png` (256 px, PNG8) generated by `tool/store/make_rock_textures.sh` from the fill tiles of the cave wall sheet `art_src/tiles/rock_tiles_src.png`, recoloured to `ThemeSpec.rockFill`; re-run it after changing a world's rock colour. `CaveDecor` places visual-only stalactites/stalagmites on cave floors/ceilings (seeded, clear of anchors and narrow passages — `test/cave_decor_test.dart`).

**Modifiers:** `LevelModifiers` per level — `gravityMul`, `fuelDrainMul`, `cargoDensityMul`, `wallFriction` (ice ≈ 0.03). They compose multiplicatively with daily-challenge multipliers; combined gravity is clamped to `kMaxGravityMul` (2.5). Worlds ramp gravity: Alien 0.85→0.5, Mine 1.1→1.3, Lava 1.4→1.7. The HUD shows a local-gravity arrow (`GravityIndicatorHud`) whenever gravity isn't 1 g.

**Ships** (`lib/game/ship/ship_spec.dart`): `ShipSpec` const data (hull scale, density, thrust, turn rate, tank, drain, damping, winch length, tint, passive-assist flags). The level picks the ship — `LevelSpec.shipId` overrides `WorldDef.defaultShipId`, which comes from a pure-Dart `<world>ShipId` const in each `specs/world_*.dart` file so `dart run` tools can see it. Kestrel (baseline, tutorial), Hopper (light, low-g Alien), Mule (heavy lifter, Mine/Lava), Skate (auto-levels against local gravity when both controls are released, Ice), Vector (hover assist: while thrusting, cancels 75% of the local pull, Orbit). Talon (`armed: true` — nose cannon + FIRE button, shots cost fuel; The Redoubt). **Steering:** rotate input ±1 is the ship's `secondsPerFullRotation` rate (what the autopilot and validator fly), and up to ±`ShipSpec.turnBoost` (Mule 1.6 to Talon 2.2) for fast turns, halved while towing. The player picks a `SteerMode` in Settings (`steer_mode`): Two-speed (default: precise up to the dial's gold notch at 55% of the stick, full boost at 75%, built up over 0.4 s while held there), Smooth (two-speed with spin-up and a glide), Agile (proportional up to the boost) or Classic (the original one-speed stick). A held turn key boosts after 0.3 s. **Engine spool:** `ShipSpec.spoolUp` (Hopper 0.08 s to Mule 0.18 s; spool-down takes half that) eases `ShipBody.throttle` toward the thrust input. Thrust, fuel burn and the hover assist all scale with it, so a short tap is a softer nudge for the same fuel per push. The plume and engine sound still start on the input (`test/engine_spool_test.dart`). Logic is pure `FlightTuning` in `lib/game/ship/flight_tuning.dart` (`test/flight_tuning_test.dart`). Ship art: `ShipSpec.sprite` (`ship_<id>.png`, 256×256, framed like `ship.png`); if missing, the Kestrel sprite is drawn with `ShipSpec.tint`. Each new ship gets a `rating_<ship>` type-rating level at the start of its world; `LevelRegistry.hasTypeRating(id)` (Kestrel = Training Grounds complete) drives the Pilot Logbook's Type Ratings list and the `fleet_qualified` achievement. Ship/field achievements: `storm_rider` (3★ with wind), `orbital_mechanic` (3★ with a well), `heavy_lifter` (deliver at ≥ 1.5 g), `test_pilot` (Test Flight daily). A level that already has stars stays unlocked even if a level is inserted before it.

**Force fields** (`FieldSpec` in `level_spec.dart`, strengths in g): `GravityZoneSpec` (replaces gravity in a feathered rect/ellipse — zero-g or sideways), `WindZoneSpec` (additive, optional gusts), `GravityWellSpec` (softened, capped point attractor). `FieldSampler` (pure Dart) is shared by runtime and validator; `ForceFieldSystem` applies only `mass × (local − base)` to ship (after launch) and cargo, so levels without fields are untouched; it also draws the fields from the same sampler (wind streaks, gravity-zone tint + chevrons, zero-g motes, contracting well rings) below the rock. Validator guardrails: wind peak ≤ 1 g and ≤ 45% of loaded thrust; spawn/cargo/goal must feel ≥ 0.3 g within 25° of straight down through a full gust cycle, or ≤ 0.2 g (drift); a cargo pod near a well or in a strong zone needs `LevelSpec.cargoClamped` (kinematic until hooked, `CargoBody.release()` on attach). Well cores are solid `WellCore` bodies (WallTag = crash), treated as rock by the validator, and must stay ≥ 1.5 m from spawn/cargo/goal. `gravityMul: 0` = zero-g level. Preview map marks `~` wind, `z` gravity zone, `0` zero-g, `o` well. Physics constants needed by pure-Dart code live in `physics_core.dart`.

**Obstacles** (`lib/game/components/obstacles.dart`): `RotatingBar` (constant angular velocity), `Pendulum` and `SlidingBlock` (kinematic velocity-tracking on analytic paths — never teleported). All carry `WallTag`, so ship contact = crash via existing handling; cargo gets batted physically.

**Rock contact** (`lib/game/ship/hull_contact.dart`, pure): cave and tutorial walls carry `RockTag` (a `WallTag` subclass), so they're forgiving. `ShipBody._onRockContact` reads the pre-solve velocity into the rock and calls `classifyHullContact`. Upright (nose within 35° of local up) on the hull's base, on ground within 40° of level, up to `kTouchdownMaxSpeed` 1.0 m/s is a *touchdown* (the ship rests). Any other touch up to `kScrapeMaxSpeed` 0.55 m/s is a *scrape*. Sliding along a wall is free, since only the speed into the rock counts. Anything faster crashes. Touches call `NarrowHaulGame._onRockTouch`: a `ShieldFlash` (deflector bubble lit at the impact, hex cells, a ripple; follows the ship; softer on a touchdown, plus a `DustPuff`), `shield_hit.wav` (one per 0.4 s), a haptic (effects at most one per 0.2 s), `scrapesThisRun`, and the first time ever a hint (`scrape_hint_seen`). Moving obstacles, turrets, reactors and well cores keep plain `WallTag`: any touch crashes. Stars and XP ignore scrapes. Tests: `test/hull_contact_test.dart` (the rule, plus real drops onto tutorial walls and cave rock).

**Defences** (Thrust layer, `components/defences.dart` + `components/combat.dart`): `TurretSpec` / `ReactorSpec` are `ObstacleSpec`s; `obstacleFromSpec(spec, theme, host)` builds them with a `CombatHost` (implemented by `NarrowHaulGame`). Turrets lead-aim (`combat/aim.dart`), need raycast line of sight (cargo blocks it), and hold fire until the ship launches. `Shell` is *not* a physics body: it moves analytically and raycasts its path each frame (no tunnelling through chain walls). Enemy shell → `onShipShot` → crash path; on cargo → impulse. Reactor: `disableHits` → turrets offline for `disableSeconds`; destroyed → meltdown countdown (`CombatStatusHud`), timeout = crash. Fuel canisters (`LevelSpec.pickups`, `FuelCellSpec`) are distance-checked components. Turrets belong only in levels flown by an armed ship (The Redoubt): an unarmed ship can't fight back. The Talon's own cannon (`ShipSpec.armed`, shots cost `fuelPerShot`) only hurts turrets and the reactor. Any ship gets the FIRE button (`HudTouchControls.showFire`) while its `WeaponRack` has something to fire (see Weapons below). Validator: turrets on a wall facing open space, never seeing spawn/cargo/goal; reactors need an armed ship; pickups open + reachable.

**Weapons** (`lib/game/ship/weapons.dart`, pure Dart): const `WeaponSpec`s in `kWeapons`: Demolition Charge (shockwave around the ship), Gravity Bomb (falls under local gravity incl. fields, passes the towed pod), Mining Laser (held beam, ammo = seconds), Seeker Missile, Flak Burst; plus `kCannon` (the Talon's gun). Every special weapon is *heavy*: it breaks moving obstacles (`Wreckable` mixin in `obstacles.dart`; bodies carry `userData = this`, removed on death → `onObstacleDestroyed`). The cannon is not, so The Redoubt's routes/demos and the autopilot are unchanged. `WeaponRack` (on `ShipBody.rack`) holds *found* ammo (supply crates, this flight only) and *carried* ammo (`ProgressService` `ammo_<id>`, kept on reset); found is spent first. Using carried ammo sets `carriedWeaponUsedThisRun` → max 2★ (`_calculateStars`); spent carried ammo is written back in `_flushAmmo` (level teardown, app backgrounded). Carried ammo stays home in dailies and demos. `CombatHost.detonate(at, weapon)` damages every `Shootable` within `blastRadius` (`_reachTo` measures to the body's surface), shoves the pod (and the ship, unless it's its own charge) and carves rock. HUD: FIRE shows the weapon's label, a chip beside it shows ammo and cycles weapons (Q / Tab on desktop).

**Rock carving** (`level/cave/terrain_carver.dart`): `TerrainCarver` works on a *copy* of the memoized `BuiltCave.field` (a restart gets the pristine cave), unions a disc per hole (`smin`), keeps the world border (1 m) and the pad floors (`padGuards`) solid, and re-extracts loops with `extractCaveLoops` (the builder's own marching squares → Chaikin → Douglas-Peucker; ~35 ms on the biggest level in a debug test) on a background isolate, one job at a time (`_scheduleCarve`; `debugSyncCarve` in tests). `CaveTerrain.applyLoops` swaps the chain fixtures and paths (glow bitmap re-rendered at most every 0.4 s); `CaveDecor.removeFloating` and `MinimapHud.updateCaveLoops` follow; ship and pod are woken so they fall if their floor went. TMX tutorial levels don't carve.

**Supply crates** (`SupplyCrate` in `defences.dart`): on cave levels flown by an unarmed ship, a 35% chance per attempt (`kCrateChance`; `--dart-define=CRATES=always|never`) of one crate with a random weapon (`crateMin`–`crateMax` units; seekers/flak only where there's machinery). Spots come from `crateSpots(spec, ship:)` (`level/cave/crate_spots.dart`, memoized): open with room to turn, reachable from the spawn, ≥ 2.5 m from the anchors, outside every obstacle sweep and well core, preferring 1–6 m off the shortest route. Never on levels with defences, never for the autopilot (`debugNoCrates`, set by `GameHarness`). Tests: `test/weapons_test.dart`, `test/terrain_carver_test.dart` (incl. ≥ 3 crate spots on every unarmed level).

**Progression:** worlds unlock by total-star gates (`WorldDef.starsRequired`: 0/8/22/40/60/80/100 — the last is The Redoubt, flown in the armed Talon); within a world, completing a level (≥1★) unlocks the next. Unlock state is *computed* from stars, not stored. Newly earned stars pay cosmetic currency × `WorldDef.rewardPerStar`. Per-level star thresholds live on `LevelDef.stars` (`StarSpec`: fuel fractions + time limit).

`ropeMaxLength` is auto-calculated as `(shipToCargoDistance + 6.0 m) × 2` at load time for both level kinds.

### Services (`lib/game/services/`)

| Service | Responsibility |
|---|---|
| `ProgressService` | Singleton backed by `shared_preferences`. Stars/best times are keyed by **string `LevelDef.saveId`** (`stars2_<id>` / `time2_<id>`) so reordering levels never corrupts saves; `init()` runs a one-time `save_v2` migration from the old index keys. Also: daily challenge completion, cosmetic currency. Call `ProgressService.init()` before `runApp`. |
| `CareerService` / `rank_service.dart` | Pilot ranks & XP. Pure rank math (`kRanks`, `rankFor`, `computeRunXp`) + persistence glue. XP stored in `xp_total`; `save_v3` migration backfills XP from existing stars/achievements. |
| `AchievementService` | Static class. `AchievementService.all` = full list; `unlocked` = Set of earned IDs. Call `unlock(id)` after win checks. |
| `MusicService` | One looping track at a time with timer crossfades: menu track on menus; in flight `flightTrackFor(themeId, keepCurrent: retry)` picks a random `flightPool` track (6, never the same twice in a row; battle in The Redoubt) at 0.28 volume × a measured per-track `_gain` (evens out loudness); results track on delivery. Playing the current track only changes its volume, so retries don't restart it. Own **Music** toggle (`music_enabled`); paused while the app is backgrounded or a full-screen ad is up (`setAdShowing`, from `MonetizationService`, which also stops the engine loop and alarm). |
| `AudioService` | Wraps `flame_audio`. Silent fallback if audio files are missing. The engine loop plays muted for the whole flight and `updateEngine` (called every frame with `ShipBody.isThrusting`) shapes its volume through the pure `ThrustEnvelope` (fast attack, 0.12 s minimum hold, soft release), because starting a media player takes 100–300 ms and swallowed short taps; `stopEngine` on pause/crash/landing. Every one-shot (shots, enemy shots from each turret `spawnShell`, booms, pickups, countdown, menu taps — `withTapSound` in `lib/ui/tap_sound.dart` wraps every overlay button) plays from a preloaded `AudioPool` (pooled players recycle; Android low-latency one-offs never report completion), and each file loads on its own so one bad file only mutes itself; `setAlarm` loops the meltdown alarm while `_meltdownLeft` runs; `playStartLevel` on a fresh level load. iOS `ambient` session (respects the silent switch), never takes audio focus from the player's music. |
| `CosmeticsService` | Categories: `catShip`, `catRope` (tow gear with real stats, see Rope/Tow System), `catPlume`. `isUnlocked`, `equip`, `unlock` (costs cosmetic currency). The shop totals 4,680 coins (≈ a full playthrough's star + rank payouts plus some dailies); the premium tier is the world liveries (200–450), Cryo/Plasma plumes, Shock Cord and the Tractor Beam. ### Monetization

Free with light ads (Alto's-style). `MonetizationService.init()` runs after `runApp`: UMP consent (GDPR; iOS ATT via the AdMob "IDFA message"), then `MobileAds.initialize`, preloads one interstitial + one rewarded. Ads exist only on Android/iOS; on macOS/tests debug builds grant rewarded placements instantly. Debug and profile builds always use Google test ad units; release builds use the real `AdIds._release*` units of the "Narrow_Haul" AdMob apps (same publisher account as zafrk; app ids in `AndroidManifest.xml` / `Info.plist`). They serve real ads only after each app is linked to its published store listing in AdMob.

- **Interstitials:** only when leaving the result screen (`leaveResults`), never after a crash/retry/level start, the daily's first clear or a rank-up. Rules in pure `ad_pacing.dart` (`AdPacing`, tested in `test/monetization_test.dart`): ≥4 lifetime deliveries and ≥300 s flown, 90 s session grace, every 3 clears, 180 s apart, 240 s after a rewarded ad, ≤4 per session, never for payers. State persisted in `ProgressService` (`ads_*`, `iap_*` keys).
- **Rewarded** (`_RewardedButton`, hidden until an ad is loaded): *continue after crash* (`continueAfterCrash` rewinds to a safe `_FlightSnapshot` ≥1.5 s before the crash — same tow state, ≥0.9 m clear, not in a strong pull; +25% fuel, enemy shells cleared, turrets quiet 3 s, world/meltdown state kept; once per attempt, not after a meltdown time-out; run capped at 2★ via `continuedThisRun`), *2× coins* on the result screen, *cosmetic trial* in the Garage (`CosmeticsService.trialOverride`, read by `getEquippedId`; cleared on `nextLevel`/`backToMenu`; `getSavedEquippedId` is the player's own choice).
- **IAP**: non-consumables `nh_remove_ads` (interstitials off; rewarded stays) and `nh_supporter_pack` (remove-ads + `ship_supporter` livery + 500 💰, paid once); consumable ammo packs `nh_demo_kit` / `nh_arsenal_crate` (`ProductIds.ammoPacks`, bought with `buyConsumable`, paid once per store transaction via `iap_tx_<purchaseID>`, never remove ads, but count as a purchase for ad pacing). The packs, coin purchases and a rewarded "+1" per weapon (`AdPlacement.ammo`) live in Garage → **Armory** (`lib/ui/armory.dart`); the game-over screen offers a rewarded Demolition Charge after 2 crashes in a row (`canOfferAmmo`). Settings has buy rows (only when the store returned the product), Restore purchases and UMP "Privacy options". UI buys go through `buyWithFeedback` / `restoreWithFeedback` (`lib/ui/store_feedback.dart`): SnackBars for pending (Ask to Buy), store unavailable, restored / nothing to restore (`purchase()` → `BuyOutcome`, `restore()` → count). A soft remove-ads offer shows on the result screen after `tut_10` or the first interstitial, at most every 3 days.
- **Debugging ads:** debug and profile builds log every decision as `MonetizationService: …` (SDK ready, ads/products loaded, and each result-screen check: `interstitial check → allowed=… deliveries=4/4 flown=128s/300s session=… clears=…`). On a fresh install the first interstitial needs ≥4 clears and 300 s flown, which is the usual reason "no ad showed". A sandbox test purchase (remove ads / any IAP) also turns interstitials off for good on that device: Settings → *Reset purchases (dev)* (non-release builds, only after a purchase) clears `ads_removed` and `iap_*`. iOS sandbox purchase sheets show a placeholder icon and "UNRATED" until a build is uploaded and an age rating is set; that's App Store Connect, not the app.

### Pilot Career (Ranks & XP)

10 realistic civil-aviation ranks (`kRanks` in `rank_service.dart`): Student → Private → Commercial Pilot → Second Officer → First Officer → Senior First Officer → Captain → Senior Captain → Training Captain → Chief Pilot (+ prestige ★ every 3000 XP). XP is awarded in `_onGoalReached`: first clear 60×tier, new stars 30×tier each, clean flight +15, PB +20, daily 150 + streak, achievements +100; tier = 1 + 0.5×world index. Runs that earn nothing new share a 300 XP/day cap. Ranks grant a currency multiplier on payouts, a one-off promotion bonus, and unlock rank-locked cosmetics (`CosmeticItem.rankRequired`). Insignia (wings / epaulette bars) is drawn by `paintInsignia` in `components/rank_insignia.dart`. The win result is exposed as `NarrowHaulGame.lastRunReward`. Lifetime stats: `ProgressService.getStat(stat*)`.

**Contracts** (`contracts_service.dart`, unlocked at Commercial Pilot): 3 daily tasks generated deterministically from the date (only feasible ones: unlocked worlds, stars left, daily not done), stored per day in `contracts_<date>` so they don't reshuffle; progress applied in `_onGoalReached` via `ContractsService.recordDelivery`, completed contracts + all-done bonus appear as XP lines. **Achievement toast:** `AchievementService.unlock(id, announce: true)` pushes to `AchievementService.announced`, shown by `_AchievementToastHost` (use only for mid-flight unlocks; win-time unlocks are listed on the level-complete screen). Mid-flight unlocks pay their XP with the delivery, or immediately on crash.

### Camera

Base zoom `_baseZoom = 28` (px/meter). `_followCamera` follows the ship at 18% per 1/60 s, eased by time, so it tracks the same at any frame rate. Clamped to world bounds so the camera never shows outside the level. Auto-scales down if world fits inside viewport. The player picks a `CameraMode` in Settings (`lib/game/ship/flight_tuning.dart`, `camera_mode`): Centred (the original), Look-ahead (default: leads 0.4 s of velocity, at most 2 m, and zooms out 12% while towing) or Wide (15% further out).

## Store assets

Sources live in `art_src/` (not bundled), and the scripts live in `tool/store/`. The Python scripts need Pillow. **`art_src/store/README.md` is the upload checklist:** what's ready, what's pending, and which file goes where in App Store Connect and Play Console.
