## Commands

```bash
flutter pub get          # Install dependencies
flutter run              # Run the game (use a landscape-capable device/simulator)
flutter test             # Run tests (~20 s; `autopilot` and `perf` tags skipped)
flutter test --tags perf --run-skipped   # wall-clock budgets (cave build, carve re-extract)
flutter analyze          # Static analysis / linting
```

There is no Makefile or custom build script — all operations go through `flutter`.

## Architecture Overview

**Narrow Haul** is a 2D physics-based Flutter game. The tech stack is:
- **Flame v1.36.0** — game engine (component/system model)
- **Forge2D v0.19.2** — Box2D physics (via `flame_forge2d`)
- **tiled v0.11** — `.tmx` parsing for the tutorial levels (`TiledLevelLoader`, no Flame Tiled renderer)
- **shared_preferences** — persistence for progress, cosmetics, achievements

`Flame.images.prefix` is set to `'assets/'` in `main()`, so all image paths are relative to `assets/` (not the default `assets/images/`).

### Game Class (`lib/game/narrow_haul_game.dart`)

`NarrowHaulGame` extends `Forge2DGame`. It is the single master controller:
- Owns the `RunState` enum (`menu | playing | gameOver | won`) and drives all state transitions
- Holds references to the active `ShipBody`, `CargoBody`, `CargoAttachment`
- Manages level lifecycle: load → play → teardown (all level entities tracked in `_levelEntities` for bulk removal)
- Reads `rotateAxis` (−1.0 to 1.0) and `thrustHeld` (bool) from `HudTouchControls` each frame, then calls `ship.setInput(...)`
- Calculates stars (1/2/3 based on remaining fuel %), saves progress, fires achievement checks after win
- Hosts the daily challenge mode (`isChallengeMode`, `activeChallengeConfig`)

### Physics System (`lib/game/physics_constants.dart`)

- **Scale:** 32 px = 1 meter (`pixelsPerMeter`). Tiled tiles are 32 px.
- **Gravity:** `kGravityY = 1.375 m/s²` (debug builds use 70% of this via `kDebugReduceGravity`)
- **Collision bitmasks:** `categoryWall=0x0001`, `categoryShip=0x0002`, `categoryCargo=0x0004`, `categoryGoalCargo=0x0008`, `categoryGoalShip=0x0010`, `categoryHook=0x0020`. Hook sensor only collides with cargo. The ship hull and the pod *do* collide (`filterShip`/`filterCargo`); the pod has rolling resistance on rock (`CargoBody.rollingDecay`), so a ship settling on it doesn't roll it off the pad.
- **Tags** in `lib/game/tags.dart` are used in `beginContact` callbacks to identify collision partners.

### Rope/Tow System

Tow gear is chosen in the Garage (rope category) and is a real **sidegrade**, not just a colour. `RopeSpec` (pure Dart, `lib/game/ship/loadout.dart`, `kRopes` keyed by the cosmetic id, `ropeById`) sets hook reach, approach distance, an elastic one-sided spring (`stiffnessHz`, `dampingRatio`, `maxStretch`), `swingDamping`, `podMassAdd` (line weight added to the towed pod), and the tractor-beam fields. The stock `rope_cable` is exactly the original rigid tow (`test/loadout_test.dart`). The lineup is: Steel Winch Cable (stock), Tow Chain (swing damping, +35% pod weight), Long Line (rank, a little give and reach), Magnetic Grapple (`rope_energy`: grabs from a hover, springy), Shock Cord (`rope_neon`: very elastic) and Tractor Beam (`rope_tractor`, 500 coins). The game reads the equipped id (trial override included) at spawn and passes the spec down. Garage rope tiles show the blurb and `RopeStats` bars.

1. **`cargo_attachment.dart`** — monitors ship–cargo distance. Fades in the line at `rope.approachDistance` (3.0 m stock). The hook is the winch under the tail (`ShipSpec.hookLocalY == rearLocalY`; the line is drawn from there before and after the catch). Auto-attaches when the winch is within `hookRadius + cargo radius + rope.hookReach` (stock `kStockHookReach` 0.6: a hover catches with ~0.8 m of air under the tail), or when the ship centre is within `rope.attachCenterDistance` (`kAttachCenterBase` 1.7 + extra reach). With a beam it locks on within `beamRange` through clear line of sight (`hasLineOfSight`) and drops the pod when the beam breaks (`onBeamLost`, 0.6 s re-lock delay).
2. **`rope_physics_coupling.dart`** — creates the Forge2D joint. Uses `RopeJoint` for normal distances (≥ 0.12 m) or `DistanceJoint` for very short distances. Ship anchor = winch at `rearLocalY`; cargo anchor = cargo world centre. `maxLength` = distance at attach, at least `rope.minTowLength` (1.0 m stock: a close catch pays the line out, slack until the ship climbs), clamped to `levelData.ropeMaxLength`. An elastic rope makes that the rest length, puts the hard cap at `× (1 + maxStretch)`, and adds a one-sided spring force each frame (it pulls, never pushes). `swingDamping` damps the pod's swing relative to the ship. Both apply equal and opposite forces to ship and pod. `podMassAdd` scales the pod's fixture density while towed and restores it on removal. Hook reach is never below stock (`test/loadout_test.dart`), because a pod on a slope rolls away from a short hook (lava_06).
3. **`tractor_beam_coupling.dart`** — beam tow with no joint. A capped PD spring (cap `beamMaxAccel` × a standard pod's mass, so heavy pods lag) pulls the pod to `beamHoldLength` below the winch along local gravity, or the ship's down axis in zero-g. A far pod is reeled in at 1.6 m/s. The reaction goes on the ship, so the pod's weight still loads it. Drains `beamFuelFracPerSec` × tank per second. Breaks on > 0.25 s without line of sight, beyond 1.1 × range, or out of fuel.
4. **`rope_line.dart`** / **`tractor_beam_line.dart`** — visuals only. The rope is a Bézier sag that thins and brightens when stretched. The beam is a gradient cone with travelling rings, a pod halo, a flicker near the force cap, and a fizzle on break. Opacity is driven by `ropeRevealProgress`.

Autopilot: `--dart-define=ROPE=<id>` flies every level with that tow gear (set in `GameHarness.loadLevel`). With a beam, the bot plans the tow at the beam's hold length, not the lock-on distance. Planned next: winch in/out, release & re-hook, beam sounds, and Engine/Tank kits.

**Garage notices** (`lib/game/services/garage_notices.dart`, pure `GarageSnapshot`, `test/garage_notices_test.dart`): an item is *fresh* while its state key (`<id>:rank` rank reached, `<id>:afford` coins enough) isn't in `garage_seen`; opening a Garage tab or the rank-up card marks it seen. Owned rope/kit never equipped (`gear_fitted_<id>`, set by `CosmeticsService.equip`) is *unused gear*. Shown as: hangar Garage tile badge (`N NEW`, else `FIT`) + subtitle (`nextGoal`: cheapest gear out of reach, then the next rank unlock, then looks), Garage tab dots and tile ribbons (NEW / AFFORDABLE / NOT FITTED), rank-up card rows with *Fit now* (`unlocksAtRank`; every rank perk string must name its items), a mission-complete note for what the payout made affordable (`newlyAffordable`, `RunReward.coinsBefore`), and the briefing's *Loadout* line with a *Fit gear* / *Garage* button (`openGarageFromBriefing`; closing the Garage returns to that briefing). The Garage asks before spending coins (*Buy & fit*), explains a refused tap (coins short / rank XP to go), captions looks vs sidegrades, and shows ▲▼ stat deltas against the equipped item.

**Handling kits** (Garage → Handling, `catKit`): `KitSpec` in `loadout.dart` (`kKits`, `kitById`), read at spawn and passed to `ShipBody.kit`. They're sidegrades that pay in fuel or tank (`test/loadout_test.dart`). Standard Fit (stock), Gyro Stabiliser (150: rights the ship when both controls are released, gentler than the Skate's; +6% fuel burn), Vernier Thrusters (200: +25% turn rate; tank −10%) and Inertial Dampers (250: +0.25 linear damping, so a 2.5 m/s drift halves in ~1.5 s instead of ~3 s; slower, +8% fuel burn). Garage tiles show the blurb and `KitStats` bars. The autopilot flies the Standard Fit, so 3★ checks don't depend on kits.

### Level System

`LevelRegistry` (`lib/game/level/level_registry.dart`) is the authoritative list: 7 `WorldDef`s → 60 `LevelDef`s (flat index = play order). Two level kinds (sealed `LevelDef` in `level_def.dart`):

1. **`TmxLevelDef`** — the 10-level Tutorial world. `.tmx` files in `assets/tiles/` (level_01…level_10). `TiledLevelLoader` parses object layer "walls" (rectangles → static bodies) and "markers" (`ship`, `goal`, `cargo_zone`, optional `fuel` canisters with float property `amount`).
2. **`CaveLevelDef`** — 50 organic cave levels in 6 themed worlds (Alien/Mine/Ice/Lava/Orbit, 8 each; Redoubt, 5) plus a `rating_<ship>` type-rating level opening the Alien, Mine, Ice, Orbit and Redoubt worlds, defined as const `LevelSpec` data in `lib/game/level/specs/world_*.dart`. **No external editor** — hand-authored Dart data.

**Cave pipeline** (`lib/game/level/cave/`): `LevelSpec` (tunnels = Catmull-Rom splines with per-point half-widths, chambers = ellipses, anchors, obstacles, modifiers) → `cave_builder.dart` samples a signed distance field (smooth-min union, seeded fbm noise for the ant-nest look, noise fades near anchors) on a 0.1 m grid → marching squares → Chaikin + Douglas-Peucker → contour loops. Loops become one static body with `ChainShape.createLoop` fixtures (`CaveTerrain` component) and an even-odd filled `Path` for rendering. The theme's blurred edge glow is pre-rendered once per level into a small bitmap (16 px/m), not blurred every frame. Deterministic: noise seed is the spec's explicit `seed` int — levels are fixed, never random. Builder is pure Dart (headless-testable) and memoized per level id (cache cleared each load in debug for hot-reload authoring). At level load `prebuildCave(spec)` builds it on a background isolate (`Isolate.run`) so the UI never freezes; later `buildCave` calls hit the cache.

**Validation:** `test/cave_level_validation_test.dart` proves every cave level completable (anchor openness, BFS reachability with ship clearance, cargo rest-point approachability, obstacle sweeps clear of anchors, determinism; the build-time budget is tagged `perf`, run on demand). Authoring aid: `dart run tool/preview_levels.dart [id]` prints ASCII maps + issues. **Run this after any spec edit.** Common authoring gotcha: a cargo pocket must be a bowl — connect its tunnel at/above the pocket center, never as a slope under the cargo, or the cargo rolls out. **Delivery pads:** the builder lays a flat rock shelf (`_layPadShelf`, 1.5 m deep, pad width + 0.4 m each side) `kPadFloorDrop` (0.3 m) below every cave pad box and clears the box above it. The win sensors (`DualLandingZone`) reach `kPadSensorDrop` (0.45 m) below the box, so a ship or the pod (r 0.28 m) resting on that floor counts (the validator's `pad not grounded`, and the `landing pads` test). Never put a pad straight above a shaft or the only way through: the shelf would plug it. Put it in a side lobe (lava_06, redoubt_04/05). `LandingStripVisual` draws a cave pad's deck on that floor (`floorDrop`) with a faint beacon column over the box. The sensors count touching fixtures (the hull has several). `DualLandingZone` latches only when `_onBothLanded` accepts (mid-flight, not a demo), and `continueAfterCrash` re-arms it (`reset` + `recheck`); see `test/landing_zone_test.dart`. Tutorial TMX goals are hover zones in the air, by design.

**Flight checks** (`analyzeFlight` in `level_validator.dart`): along the shortest 8-connected route spawn → cargo → goal, *lift* = loaded thrust accel ÷ strongest pull at the heaviest daily gravity (must be ≥ 2.0), and *fuel* = impulse floor ∫|pull + hull drag·v|/a_thrust dt at 2.5 m/s cruise × 1.3 overhead (must be ≤ 60% of tank). Clearance and both checks use the level's ship. The preview tool prints these per level and warns `⚠ 3★ tight` when the estimate exceeds the 3★ fuel budget. Fuel canisters within 1.2 m of that route are credited (capped by what's been burned by then). This is only a floor estimate — the autopilot below is the real check.

**Autopilot flight test** (`test/autopilot/`, tag `autopilot`, skipped in normal runs): `flutter test test/autopilot --run-skipped --dart-define=STORE_CAPTURE=true [--dart-define=LEVELS=a,b]` flies every level headless through the real `NarrowHaulGame` (`test/autopilot_smoke_test.dart` flies tut_01 and alien_01, plus a tractor-beam tow, on every default run) (fixed 1/60 s steps, same `rotateAxis/thrustHeld/fireHeld` inputs as the HUD) and writes `build/autopilot_report.md` + `.json`: bot fuel/time per level (hazards on, and a clean run with `debugSkipHazards`), the expected player cost (bot × `kHumanFuelFactor`/`kHumanTimeFactor` = 1.3) against the 3★ thresholds, and suggested fuel canisters for tight levels. It fails unless every level passes or is in `kNeedsHumanPlaytest`. Routes come from `route_planner.dart` (`NavGrid`: clearance distance map, clearance-weighted A*; turret domes/reactors are solid). The bot (`autopilot.dart`) flies four `PilotProfile`s and keeps the best; moving obstacles are predicted via `obstacle_paths.dart` and crossed by deterministic trial and error over hold times (`_tactics`), turrets are sniped from hidden firing points (reactor first), or in *assault* mode shot from inside their view (turrets covering the tow route are cleared first, on the way to the pod), or dodged; enemy shells are dodged reactively. Each flight records time spent in a live turret's view and kills. Debug knobs: `PROFILE=`, `TRACE=<frames>`, `NOSEARCH=true`, `DODGE=true` / `ASSAULT=true` (with NOSEARCH), `CLEAN=true`. The report also ranks levels by a difficulty score (0–100: fuel margin, time margin, profiles that failed, time spent waiting at hazards; pure `test/autopilot/difficulty.dart`, thresholds `kTight*`) with a label: 3★ comfortable / 3★ tight / 3★ needs help / bot can't pass. `EXPORT_ROUTES=true` writes each delivered level's flight (most careful 3★ profile; on armed levels the 3★ flight with the most turret kills, then the least time under fire) to `assets/routes/<saveId>.json` for the route guide. Calibrate the 1.3 margin with real flights: debug builds print `RUN <id> fuelLeft=… time=… stars=…` on every delivery.

**Route guide & demo flight** (`lib/game/route/`, `components/route_guide.dart`, `ui/route_guide_overlays.dart`): `FlightRecorder` records every flight (ship pose, pod, tow/thrust, shots) every 0.1 s on the *level-load* clock, so a replay stays in step with obstacles; delivery leaves it in `lastFlightRoute` (the autopilot exports this). `RouteRepository` loads the bundled `assets/routes/<saveId>.json` (ignored if recorded with another ship, never in a daily). After 3 crashes in a row on a level (`CrashStreak`, reset by a delivery), or once a level's route is unlocked (`route_unlocked_<id>`, free, no ad), the game-over screen offers *Show route* (dotted `RouteGuideLine` + translucent `RouteGhost` timed from launch; pause-menu toggle; a guided flight is capped at 2★ via `guidedThisRun`) and *Watch a demo* (`demoMode`: level reloaded with the engine paused, ship + pod kinematic along the recording, `CargoAttachment.scriptedTow` instead of a rope joint, turrets are live once the replay passes the recorded launch — their timing is seeded per turret and runs on the level-load clock, so they fire the shells the bot survived; a shell reaching the demo ship just vanishes, counted in `demoShellHits` — recorded shots are replayed as the very same shells — `FlightRoute.shotRays` stores each shot's muzzle and velocity — no meltdown, no stars/stats). On the guide line, dots a live turret covers (`Turret.covers`) are red, a crosshair with a dashed aim ray marks each recorded shot burst (`FlightRoute.fireMarks()`), a dashed ring marks where the flight held still ≥ 0.8 s, and the ghost shows a muzzle flash at shot times. `test/route_test.dart` checks every bundled route still starts on the spawn, hooks the pod, ends on the pad and stays out of rock, and that every level has one (60 routes, ~780 KB); `test/route_demo_test.dart` checks that each turret level's demo is never hit and its shot bursts knock something out — re-export a level (`LEVELS=<id> EXPORT_ROUTES=true`) after editing it.

**Theming:** `ThemeSpec` per world (`lib/game/level/theme_spec.dart`) — backdrop, rock palette, parallax tint/alphas, pad + UI accent colors, edge glow, decor tip color/density, `AmbientKind` particles. Applied in `_spawnLevel`. Optional art in `assets/themes/<id>/` (`rock.png`, `far/mid/near.png`, `decor.png` — spec in `assets/themes/README.md`) is loaded by `ThemeAssets`; every file falls back to the flat look (shared tinted parallax `assets/{far,mid,near}.webp`, solid rock, procedural spikes). Every world ships a `rock.png` (256 px, PNG8) generated by `tool/store/make_rock_textures.sh` from the fill tiles of the cave wall sheet `art_src/tiles/rock_tiles_src.png`, recoloured to `ThemeSpec.rockFill`; re-run it after changing a world's rock colour. `CaveDecor` places visual-only stalactites/stalagmites on cave floors/ceilings (seeded, clear of anchors and narrow passages — `test/cave_decor_test.dart`). **Cargo size:** `kCargoGrowth` 3.0 (`physics_core.dart`) makes the pod r 0.28 m, art and collision together; `kCargoDensity` shrinks by growth², so its mass (lift, tractor beam, validator) is the original's. **Cargo art:** a world's `cargo.png` (and `cargo_heavy.png`, used on its `cargoDensityMul > 1` levels) replaces the shared `assets/cargo.png` (`ThemeAssets.cargoFor`, passed to `CargoBody(image:)`). The art is drawn at the collision size (`CargoBody._spriteHalf`). A heavy pod without its own art gets two steel straps drawn over it (`CargoBody.strapped`).

**Modifiers:** `LevelModifiers` per level — `gravityMul`, `fuelDrainMul`, `cargoDensityMul`, `wallFriction` (ice ≈ 0.03). They compose multiplicatively with daily-challenge multipliers; combined gravity is clamped to `kMaxGravityMul` (2.5). Worlds ramp gravity: Alien 0.85→0.5, Mine 1.1→1.3, Lava 1.4→1.7. The HUD shows a local-gravity arrow (`GravityIndicatorHud`) whenever gravity isn't 1 g.

**Ships** (`lib/game/ship/ship_spec.dart`): `ShipSpec` const data (hull scale, density, thrust, turn rate, tank, drain, damping, winch length, tint, passive-assist flags). The level picks the ship — `LevelSpec.shipId` overrides `WorldDef.defaultShipId`, which comes from a pure-Dart `<world>ShipId` const in each `specs/world_*.dart` file so `dart run` tools can see it. Kestrel (baseline, tutorial), Hopper (light, low-g Alien), Mule (heavy lifter, Mine/Lava), Skate (auto-levels against local gravity when both controls are released, Ice), Vector (hover assist: while thrusting, cancels 75% of the local pull, Orbit). Talon (`armed: true` — nose cannon + FIRE button, shots cost fuel; The Redoubt). **Steering:** rotate input ±1 is the ship's `secondsPerFullRotation` rate (what the autopilot and validator fly), and up to ±`ShipSpec.turnBoost` (Mule 1.6 to Talon 2.2) for fast turns, halved while towing. The player picks a `SteerMode` in Settings (`steer_mode`): Two-speed (default: precise up to the dial's gold notch at 55% of the stick, full boost at 75%, built up over 0.4 s while held there), Smooth (two-speed with spin-up and a glide), Agile (proportional up to the boost), Point (the nose turns toward the stick's screen direction: `pointerAxis`, a proportional controller that closes the error in ~0.12 s, capped at the boost, ignoring a resting thumb under 30% of the throw; the dial draws a heading needle) or Classic (the original one-speed stick). A held turn key boosts after 0.3 s. Logic is pure `FlightTuning` in `lib/game/ship/flight_tuning.dart` (`test/flight_tuning_test.dart`). **Hull = art:** the sprite is drawn at `ShipSpec.artMetersPerPx` (0.0068 × `hullGrowth` 1.6 = 0.0109 m/px × `hullScale`, both axes, nozzle row 181 on `rearLocalY` = 0.39 × 1.6 — about as tall as the pre-trace sprite looked; `ShipSpec.spriteRect`, shared by `ShipBody` and the route ghost). The collision hull is traced from each ship's own sprite as convex `HullSection`s (`kKestrelHull`…, a few px inside the art) → `hullPolygons`, one fixture each. `noseLocalY`, `hookLocalY` (0.15 m behind the tip), `circumradius` (validator clearance, ~0.8–1.06 m; mine_06's bar chamber, lava_05's block period and orbit_06's pod were eased for 1.25, ice_06's pad shaft (enters the pad lobe from the side), orbit_05's tunnels (2.1) and mine_08's bar chamber (3.5) for 1.6; at 1.6 the Mule flies at `hullScale` 1.0, Kestrel-sized, with density 1.3 × 1.1² so its flight mass is unchanged, because its obstacle levels were built around a smaller hull; tut_07, ice_03 and lava_07's 3★ fuel lines dropped 5 points) and the rock probe derive from it. Flight mass, balance and inertia stay the original triangle hull's (`mass`, `massCenterY`, `massInertia`, set with `setMassData`), so flight feel is unchanged. Re-trace a ship's `HullSection`s when its art changes (`test/ship_and_fields_test.dart` keeps them inside the sprite). Ship art: `ShipSpec.sprite` (`ship_<id>.png`, 256×256, framed like `ship.png`); if missing, the Kestrel sprite is drawn with `ShipSpec.tint`. Each new ship gets a `rating_<ship>` type-rating level at the start of its world; `LevelRegistry.hasTypeRating(id)` (Kestrel = Training Grounds complete) drives the Pilot Logbook's Type Ratings list and the `fleet_qualified` achievement. Ship/field achievements: `storm_rider` (3★ with wind), `orbital_mechanic` (3★ with a well), `heavy_lifter` (deliver at ≥ 1.5 g), `test_pilot` (Test Flight daily). A level that already has stars stays unlocked even if a level is inserted before it.

**Fleet** (`lib/game/ship/fleet.dart` pure, `services/fleet_service.dart`, `test/fleet_test.dart`): the pilot picks the ship. Each level keeps its *par ship* (`LevelRegistry.shipFor`: balance, validator, routes, autopilot). Any other owned ship flies it when `shipFitOn` says `ok`. For cave levels that comes from `kShipFitTable` (`lib/game/level/ship_fit_table.dart`, generated by `dart run tool/gen_ship_fit.dart` from `validateCaveSpec` per ship, sorted by `classifyFitIssues` into tooBig / lowLift / lowFuel / needsCannon). **Re-run it after any spec or ship edit**; `test/ship_fit_table_test.dart` fails until you do. TMX maps use `tmxShipFit` (hull no larger, ≥ 90% range). `rating_*` missions fly only the par ship (`parOnly`). `resolveFlownShip`: the briefing choice for that level (`ship_choice_<saveId>`), else the Garage default (`ship_preferred`), else par. Each only counts if owned and fit. Dailies, demos and route-guided runs always fly their own ship (`_loadCurrentLevel`), and the *With route* button and pause toggle need the par ship (`flyingParShip`). **Stars stay fair:** off par, `_calculateStars` rates `normalisedFuelLeft` (tank share burned × flown ΔV ÷ par ΔV; time unchanged). Calibrate it with `--dart-define=SHIP=<id>` on the autopilot (fleet pass + default ship; routes never exported). **Owning a ship:** Kestrel stock, a ship's type rating, coins (`kShipCoinPrice` 400–1,200, `ship_owned_<id>`, cleared on reset) or the one ship IAP, the Fleet Pass (`nh_fleet_pass` $3.99: every ship, now and later; kept on reset). No per-ship products: single ships are a coin purchase. The Fleet Pass never removes ads (own branch in `grant()`), but counts as a purchase for ad pacing. Where the player sees it: the Garage **Ships** tab (`lib/ui/garage_ships.dart`: *Mission ship* row = no default, `ShipTile` with `ShipStatsView` bars LIFT/TURN/RANGE/STEADY/SMALL ▲▼ against the default, "Flies N of 60 missions", `ShipOfferDialog` = earn / coins / Fleet Pass), and the briefing ship chip (`_ShipPicker`: a menu of the fleet with why-not reasons and *Get more ships…* → `openGarageFromBriefing(tab: GarageOverlay.shipsTab)`). Notices: `FleetService.fresh` (`ship_<id>:rated` / `:afford` in `garage_seen`) adds to the hangar badge and dots the Ships tab. Achievement `off_type` (3★ off par). Analytics: `ship_unlock` (rating / coins / iap), `ship_selected`, `par_ship` on `level_start`, `ship` on `level_end`. Store screenshots: `--dart-define=FLEET_PREVIEW=true` shows every ship but the Kestrel locked and the Fleet Pass offer without a store (`kFleetPreview`). Planned: 1–2 bonus hulls (no par levels of their own, in the Fleet Pass).

**Force fields** (`FieldSpec` in `level_spec.dart`, strengths in g): `GravityZoneSpec` (replaces gravity in a feathered rect/ellipse — zero-g or sideways), `WindZoneSpec` (additive, optional gusts), `GravityWellSpec` (softened, capped point attractor). `FieldSampler` (pure Dart) is shared by runtime and validator; `ForceFieldSystem` applies only `mass × (local − base)` to ship (after launch) and cargo, so levels without fields are untouched; it also draws the fields from the same sampler (wind streaks, gravity-zone tint + chevrons, zero-g motes, contracting well rings) below the rock. Validator guardrails: wind peak ≤ 1 g and ≤ 45% of loaded thrust; spawn/cargo/goal must feel ≥ 0.3 g within 25° of straight down through a full gust cycle, or ≤ 0.2 g (drift); a cargo pod near a well or in a strong zone needs `LevelSpec.cargoClamped` (kinematic until hooked, `CargoBody.release()` on attach). Well cores are solid `WellCore` bodies (WallTag = crash), treated as rock by the validator, and must stay ≥ 1.5 m from spawn/cargo/goal. `gravityMul: 0` = zero-g level. Preview map marks `~` wind, `z` gravity zone, `0` zero-g, `o` well. Physics constants needed by pure-Dart code live in `physics_core.dart`.

**Obstacles** (`lib/game/components/obstacles.dart`): `RotatingBar` (constant angular velocity), `Pendulum` and `SlidingBlock` (kinematic velocity-tracking on analytic paths — never teleported). All carry `WallTag`, so ship contact = crash via existing handling; cargo gets batted physically.

**Rock contact** (`lib/game/ship/hull_contact.dart`, pure): cave and tutorial walls carry `RockTag` (a `WallTag` subclass), so they're forgiving. `ShipBody._onRockContact` reads the pre-solve velocity into the rock and calls `classifyHullContact`. Upright (nose within 35° of local up) on the hull's base, on ground within 40° of level, up to `kTouchdownMaxSpeed` 1.0 m/s is a *touchdown* (the ship rests). Any other touch up to `kScrapeMaxSpeed` 0.55 m/s is a *scrape*. Sliding along a wall is free, since only the speed into the rock counts. Anything faster crashes. Touches call `NarrowHaulGame._onRockTouch`: a `ShieldFlash` (deflector bubble lit at the impact, hex cells, a ripple; follows the ship; softer on a touchdown, plus a `DustPuff`), `shield_hit.wav` (one per 0.4 s), a haptic (effects at most one per 0.2 s), `scrapesThisRun`, and the first time ever a hint (`scrape_hint_seen`). Moving obstacles, turrets, reactors and well cores keep plain `WallTag`: any touch crashes. Stars and XP ignore scrapes. **Early warning:** each frame `probeRockNearby` (`components/rock_proximity.dart`, 12 raycasts at `WallTag` surfaces; the gap is measured from the hull's own edge) feeds `ShieldGlow`. Within 1 m an arc glows on the facing side of the shield, brighter the closer the rock. Machinery, turrets, reactors and well cores (`RockNearby.lethal`, not `RockTag`) are always red. Rock is cyan while the speed into it is safe and goes amber to red as it nears the crash limit (the touchdown limit when coming down upright onto flat ground). One light buzz, at most one per 1 s, when a crash-speed approach is under 0.5 m away. Tests: `test/hull_contact_test.dart` (the rule, plus real drops onto tutorial walls and cave rock).

**Ship look** (`components/ship_fx.dart`, visual only): lighting is pre-baked. At load `hullLightAtlas` (on `compute`, cached per sprite + rim colour, last 3 kept, skipped in `flutter test` where the hull is drawn flat) turns the sprite into normals (`hullNormals`: bevel + low dome from the alpha's distance field, grooves only on thin dark lines darker than their 5×5 surroundings) and bakes 16 premultiplied overlays, one per angle, into a 4×4 atlas (`bakeHullLightAtlas`): faces away from the world-fixed key light up to `HullLighting.maxDark` (28%) darker, faces toward it a little brighter, a warm glint on bevels facing the light, and a rim in the theme's `edgeGlow` (else a neutral cool white). `HullLighting.draw` cross-fades the two buckets nearest `body.angle` with plain `srcOver`, so highlights stay put while the ship turns. Don't light with `ColorFilter.matrix` or `multiply`/`plus` layers, or a fragment shader: Skia and Impeller disagree on colour-matrix semantics (the Mule went black on the iPhone), and `FlutterFragCoord` is in device space. `test/ship_look_test.dart` bakes every ship's real sprite and checks that no pixel ever goes more than `maxDark` darker. `ShipLook` (pure) eases a bank from the pose's angle change (so demos bank too; the hull narrows 12%), the engine level (the `ThrustPlume` grows/fades with it; `EngineHeat` glows at the nozzle after a burn) and RCS demand (`RcsPuffs`, world-space puffs at the nose and the opposite wing tip on turn starts/stops). `NavLights`: red/green wing tips, white double strobe, red spine beacon (`HullPoints.of(spec)` from the hull polygons).

**Ship showcase** (`lib/ui/ship_showcase.dart`, `test/ship_showcase_test.dart`): the ship on a display stand outside a flight, a 3D look from the 2D art. The real sprite with its baked hull lighting (`hullLightAtlas`, so highlights sweep as it turns), livery tint, plume bursts, engine heat and nav lights, drawn through a perspective `Matrix4` on a holo pad tilted back, with stacked solid-colour silhouette slices for hull thickness and a shadow on the pad; it spins (14 s a turn) and can be dragged. Still in widget tests and with reduced motion. Shown in the Garage on the Liveries and Plumes tabs beside the list (≥ 600 px wide): tapping any livery or plume previews it on the ship, owned or not, and arrows switch between the next mission's ship and every type-rated ship (`garageFleet`). The mission briefing shows the mission's ship on a 120 px stand when the dialog has room (never on a Test Flight day). Livery tints and plume colours for it live in `lib/game/ship/livery.dart` (`kLiveryTints`, `plumePalette`), copies of `ShipBody._skinTints` and `ThrustPlume`'s colours until those use it.

**Defences** (Thrust layer, `components/defences.dart` + `components/combat.dart`): `TurretSpec` / `ReactorSpec` are `ObstacleSpec`s; `obstacleFromSpec(spec, theme, host)` builds them with a `CombatHost` (implemented by `NarrowHaulGame`). Turrets lead-aim (`combat/aim.dart`), need raycast line of sight (cargo blocks it), and hold fire until the ship launches. `Shell` is *not* a physics body: it moves analytically and raycasts its path each frame (no tunnelling through chain walls). Enemy shell → `onShipShot` → crash path; on cargo → impulse. Reactor: `disableHits` → turrets offline for `disableSeconds`; destroyed → meltdown countdown (`CombatStatusHud`), timeout = crash. Fuel canisters (`LevelSpec.pickups`, `FuelCellSpec`) are distance-checked components. Turrets belong only in levels flown by an armed ship (The Redoubt): an unarmed ship can't fight back. The Talon's own cannon (`ShipSpec.armed`, shots cost `fuelPerShot`) only hurts turrets and the reactor. Any ship gets the FIRE button (`HudTouchControls.showFire`) while its `WeaponRack` has something to fire (see Weapons below). Validator: turrets on a wall facing open space, never seeing spawn/cargo/goal; reactors need an armed ship; pickups open + reachable. **Shot interception** (`combat/intercept.dart`, pure; `test/intercept_test.dart`): player fire stops turret shells. `_interceptShells` sweeps each pair of rounds over the frame (`sweptCircleHit`, `kInterceptRadius` 0.25 m, `Shell.prevPos`). A turret shell has strength 1, a player round its weapon's `damage` (cannon 1): equal trades both (cannon, flak pellet), stronger pierces and flies on (seeker, bomb). Blasts (`detonate`: charge, bomb, seeker) clear shells within `blastRadius`, and the live mining-laser beam burns shells crossing it. Each kill: small burst, `playIntercept`, stat `shells_intercepted`.

**Weapons** (`lib/game/ship/weapons.dart`, pure Dart): const `WeaponSpec`s in `kWeapons`: Demolition Charge (shockwave around the ship), Gravity Bomb (falls under local gravity incl. fields, passes the towed pod), Mining Laser (held beam, ammo = seconds), Seeker Missile, Flak Burst; plus `kCannon` (the Talon's gun). Every special weapon is *heavy*: it breaks moving obstacles (`Wreckable` mixin in `obstacles.dart`; bodies carry `userData = this`, removed on death → `onObstacleDestroyed`). The cannon is not, so The Redoubt's routes/demos and the autopilot are unchanged. `WeaponRack` (on `ShipBody.rack`) holds *found* ammo (supply crates, this flight only) and *carried* ammo (`ProgressService` `ammo_<id>`, kept on reset); found is spent first. Using carried ammo sets `carriedWeaponUsedThisRun` → max 2★ (`_calculateStars`); spent carried ammo is written back in `_flushAmmo` (level teardown, app backgrounded). Carried ammo stays home in dailies and demos. `CombatHost.detonate(at, weapon)` damages every `Shootable` within `blastRadius` (`_reachTo` measures to the body's surface), shoves the pod (and the ship, unless it's its own charge) and carves rock. HUD: the FIRE pad shows the loaded weapon's icon (`drawWeaponGlyph` in `hud_holo.dart`), label + ammo, an ammo ring (pips, or a bar for the laser) and a `−★` badge while the next shot would spend carried ammo (`WeaponRack.costsStar`). With more than one weapon on board, the *ammo rail* (`_WeaponRail`) is a column of hex slots on the screen-centre side of THRUST/FIRE: tap one to load it (`selectWeapon`); after a switch the loaded slot shows the weapon's full name for 1.2 s. The game feeds it a `WeaponHud` from `_syncWeaponHud`; the geometry is the pure `HudButtonLayout` (clear of the minimap and fuel gauge at every phone size, `test/fire_controls_test.dart`). Desktop: Q / Tab cycles, 1–6 pick a slot. A swipe-on-FIRE picker and a radial wheel were considered and deferred until the rail has been tried on a phone.

**Rock carving** (`level/cave/terrain_carver.dart`): `TerrainCarver` works on a *copy* of the memoized `BuiltCave.field` (a restart gets the pristine cave), unions a disc per hole (`smin`), keeps the world border (1 m) and the pad floors (`padGuards`) solid, and re-extracts loops with `extractCaveLoops` (the builder's own marching squares → Chaikin → Douglas-Peucker; ~35 ms on the biggest level in a debug test) on a background isolate (`extractCaveLoopsInBackground`, top-level so the closure can't capture the game, which an isolate can't receive), one job at a time (`_scheduleCarve`; `debugSyncCarve` in tests). `CaveTerrain.applyLoops` swaps the chain fixtures and paths (glow bitmap re-rendered at most every 0.4 s); `CaveDecor.removeFloating` and `MinimapHud.updateCaveLoops` follow; ship and pod are woken so they fall if their floor went. TMX tutorial levels don't carve.

**Supply crates** (`SupplyCrate` in `defences.dart`): on cave levels flown by an unarmed ship, a 35% chance per attempt (`kCrateChance`; `--dart-define=CRATES=always|never`) of one crate with a random weapon (`crateMin`–`crateMax` units; seekers/flak only where there's machinery). Spots come from `crateSpots(spec, ship:)` (`level/cave/crate_spots.dart`, memoized): open with room to turn, reachable from the spawn, ≥ 2.5 m from the anchors, outside every obstacle sweep and well core, preferring 1–6 m off the shortest route. Never on levels with defences, never for the autopilot (`debugNoCrates`, set by `GameHarness`). Tests: `test/weapons_test.dart`, `test/terrain_carver_test.dart` (incl. ≥ 3 crate spots on every unarmed level).

**Mystery salvage** (`lib/game/salvage/salvage.dart`, pure; `components/salvage_fx.dart`): a bobbing "?" cache (`SalvageCache`) on any cave level and ship, 40% per attempt (`kSalvageChance`; `--dart-define=SALVAGE=always|never|<effect>`, an effect name like `swarmSting` also forces what's inside). Spots come from `salvageSpots` (the crate rules, plus defended levels outside every turret's view, `turretMightSee`). Flying through it spins a 0.9 s roulette on the `SalvageHud` badge (top left under the fuel gauge), then `pickSalvage` applies one of 19 effects (`kSalvage`, one at a time in `ActiveSalvage`).
- **Boons (70%):** Overshield (absorbs one crash or shell), Top-off (+30% tank), Afterburner (+40% thrust), Fuel Saver (no drain), Stealth Field (turrets can't lock, `CombatHost.shipCloaked`), Compactor (hull 0.7×), Chrono (the cave runs at 0.6×: `update` scales dt by `salvage.timeScale`, effect timers use `_realDt`), Anti-grav (half the pull on ship and pod), Lucky Salvage (+60 coins on delivery, lost on a crash), Ammo Cache (a crate's weapon, unarmed ships).
- **Curses (30%):** Swarm Sting (hull 1.25×, spin to shake the bee off), Fuel Leak (double drain, a touchdown patches it), Spore Trip (`shaders/spore.frag` through `SporePostProcess` on `camera.postProcess`, plus the `SalvageScreenFx` colour drift, which is all you get if the shader fails to load), Crossed Wires (steering swaps, never within 4 m of the pad), Sputter (`ShipBody.sputtering` cuts the engine 0.2 s each second), Blackout (`SalvageScreenFx` headlamp cone), Hiccups (yaw kicks + shake), Heavy Heart (+40% pod weight while towing), Flare Beacon (`CombatHost.shipFlared`: turrets reload 1.5× faster).
- **Context:** `SalvageContext` filters (turrets, tow, armed, low fuel). World weights (`worldWeights`: spores in alien, blackout in ice, leak in lava, sputter in mine).
- **Fairness:** never two curses in a row (85% boon after one), no curse within 4 m of the pad, a crash in the first 1.5 s of a curse is forgiven. Size changes grow only into free space (`_swellStep` eases the ship off a floor or wall and waits when wedged; `ShipBody.setSizeMul` rebuilds the hull fixtures and keeps the mass). Boons never cap stars.
- **Rewards:** a delivery after a curse pays a *Grit* XP line and coins.
- **Daily:** *Salvage Chaos* (`DailyChallengeConfig.chaos`, cave levels only) drops 3 caches at 50/50. Every daily is seeded from the date.
- **Meta:** Pilot Logbook → *Salvage log* (`ProgressService.salvageFound`, silhouettes until found). Achievements: Opened the Box, Gambler (50), Ghost Protocol, Bee-lieve It, Bad Trip Good Landing, Shake It Off, Four-Leaf Clover (3 boons in a row, `stat_salvage_boon_streak`), Salvage Collector (all 19, +300 coins). Contracts: `salvageDelivery` and `cursedDelivery` (offered once a cave world is open).
- **Exclusions:** never in demos, never for the autopilot (`debugNoSalvage`, off by default under `flutter test`).
- **Sounds:** `curse.wav`, `size_up.wav`, `size_down.wav`, loops `bee_loop.wav` / `spore_loop.wav` (`AudioService._LoopPlayer`, shared with the alarm).
- **Analytics:** `salvage_opened`. Stats: `salvage_opened/curses/grit`.
- **Tests:** `test/salvage_test.dart`.

**Progression:** worlds unlock by total-star gates (`WorldDef.starsRequired`: 0/8/22/40/60/80/100 — the last is The Redoubt, flown in the armed Talon); within a world, completing a level (≥1★) unlocks the next. Unlock state is *computed* from stars, not stored. Newly earned stars pay cosmetic currency × `WorldDef.rewardPerStar`. Per-level star thresholds live on `LevelDef.stars` (`StarSpec`: fuel fractions + time limit).

`ropeMaxLength` is auto-calculated as `(shipToCargoDistance + 6.0 m) × 2` at load time for both level kinds.

### Expeditions (Act II, multi-leg hauls)

An Expedition is one long cave with several hauls (`LevelSpec.expedition(legs: [LegSpec(pod, pad), …])`; `legs`, `allLegs`, `isExpedition`). Leg 1's pod and pad are also `cargoSpawn` / `goal`, so single-haul tools still see something sensible. The builder calms the rock around every anchor (`anchorPoints`) and lays a shelf under every pad (`allGoals`). The validator checks each leg on its own (`forLeg(k)`: the ship starts on the previous pad at `legShipSpawn`, later pods are clamped, full tank), and issues are prefixed `leg N:`. `analyzeLegs` gives per-leg flight estimates. The preview tool numbers pods `1 2 3` and pads `A B C`. Specs live in `specs/expeditions.dart` (`exp_00` *Lifeline Convoy*, hand-built: 3 legs, ~125 m, Hopper). They form the world `expeditions` ("The Long Night", `WorldDef.expedition`), which sits outside the career: `LevelRegistry.career` / `careerLevels`, `totalStars()` counts career stars only (gates, hangar, logbook, contracts, the "every mission" award), and dailies and contracts never pick one (`isExpedition`).

Runtime (`narrow_haul_game.dart`, `LevelData.legs` / `LegData`):
- **Pods and pads:** every leg's pod spawns at load, with later pods locked. Every pad is drawn. Only the current leg has a tow line (`_towFor`) and win sensors (`_padFor`).
- **Landing a leg (not the last):** `_onBothLanded` sets `_legLanded`, and the next frame's `_advanceLeg` runs. It can't run inside the contact callback, because the world is locked during the physics step. `_advanceLeg` parks the pod (`CargoBody.lock`) and refuels to full. It saves the checkpoint (`_checkpointLeg`, the clock, fuel left per pad) and clears the continue snapshots. It then arms the next pod and pad (`cargo`, `cargoAttachment`, `_landingZone`, `ForceFieldSystem.cargo`), plays a burst, and puts an OPS line plus `BeatCue.landed` story beats on the radio.
- **HUD:** shows `Leg n/N`. The minimap shows the current pad (`currentLeg`).
- **Crash screen:** offers *Resume · pad N* (`canResumeFromPad`, `resumeFromPad`). This reloads the level at that leg, with earlier pods parked (`parkedPod`), the clock restored, and the run capped at 2★ (`checkpointUsedThisRun`). *Restart* starts over.
- **Stars:** rate the mean fuel left over every pad.
- **Story beats:** `StoryBeat.leg` limits a beat to one leg.
- **Not built yet:** no route guide or demo for Expeditions, and the autopilot skips them (multi-leg flying is X3). Tests: `test/expedition_test.dart`.

### Monetization

Free with light ads (Alto's-style). `MonetizationService.init()` runs after `runApp`: UMP consent (GDPR; iOS ATT via the AdMob "IDFA message"), then `MobileAds.initialize`, preloads one interstitial + one rewarded. Ads exist only on Android/iOS; on macOS/tests debug builds grant rewarded placements instantly. Debug and profile builds always use Google test ad units; release builds use the real `AdIds._release*` units of the "Narrow_Haul" AdMob apps (same publisher account as zafrk; app ids in `AndroidManifest.xml` / `Info.plist`). They serve real ads only after each app is linked to its published store listing in AdMob.

- **Offline:** the game plays fully offline with no ads: nothing waits for an ad, rewarded buttons stay hidden, buy rows hide and a tap that needs the store says it needs a connection. Ads and store set up in parallel; whatever failed (consent/SDK, products, ad loads) is retried by `refreshIfNeeded()` on app resume and when the hangar or a sub-screen opens (throttled 30 s). Failed ad loads back off 60 s → 10 min (`adRetryDelay`). Firebase init is capped at 5 s before `runApp`.
- **Interstitials:** only when leaving the result screen (`leaveResults`), never after a crash/retry/level start, the daily's first clear or a rank-up. Rules in pure `ad_pacing.dart` (`AdPacing`, tested in `test/monetization_test.dart`): ≥4 lifetime deliveries and ≥300 s flown, 90 s session grace, every 3 clears, 180 s apart, 240 s after a rewarded ad, ≤4 per session, never for payers. State persisted in `ProgressService` (`ads_*`, `iap_*` keys).
- **Rewarded** (`_RewardedButton`, hidden until an ad is loaded): *continue after crash* (`continueAfterCrash` rewinds to a safe `_FlightSnapshot` ≥1.5 s before the crash — same tow state, ≥0.9 m clear, not in a strong pull; +25% fuel, enemy shells cleared, turrets quiet 3 s, world/meltdown state kept; once per attempt, not after a meltdown time-out; run capped at 2★ via `continuedThisRun`), *2× coins* on the result screen, *cosmetic trial* in the Garage (`CosmeticsService.trialOverride`, read by `getEquippedId`; cleared on `nextLevel`/`backToMenu`; `getSavedEquippedId` is the player's own choice).
- **IAP**: non-consumables `nh_remove_ads` (interstitials off; rewarded stays), `nh_supporter_pack` (remove-ads + `ship_supporter` livery + 500 💰, paid once) and `nh_fleet_pass` (every ship; never removes ads, see **Fleet**); consumable ammo packs `nh_demo_kit` / `nh_arsenal_crate` (`ProductIds.ammoPacks`, bought with `buyConsumable(autoConsume: false)` and consumed on Android only after `grant` (`_consumeIfNeeded`; a failed consume leaves the purchase unfinished, so the startup restore re-delivers it), paid once per store transaction via `iap_tx_<purchaseID>`, never remove ads, but count as a purchase for ad pacing). A buy settles only on an event for its own product (`_settle`); a second tap while one is open is ignored for 2 min. The packs, coin purchases and a rewarded "+1" per weapon (`AdPlacement.ammo`) live in Garage → **Armory** (`lib/ui/armory.dart`); the game-over screen offers a rewarded Demolition Charge after 2 crashes in a row (`canOfferAmmo`). Settings has buy rows (only when the store returned the product), Restore purchases and UMP "Privacy options". UI buys go through `buyWithFeedback` / `restoreWithFeedback` (`lib/ui/store_feedback.dart`): SnackBars for pending (Ask to Buy), store unavailable, restored / nothing to restore (`purchase()` → `BuyOutcome`, `restore()` → count). A soft remove-ads offer shows on the result screen after `tut_10` or the first interstitial, at most every 3 days.
- **Debugging ads:** debug and profile builds log every decision as `MonetizationService: …` (SDK ready, ads/products loaded, and each result-screen check: `interstitial check → allowed=… deliveries=4/4 flown=128s/300s session=… clears=…`). On a fresh install the first interstitial needs ≥4 clears and 300 s flown, which is the usual reason "no ad showed". A sandbox test purchase (remove ads / any IAP) also turns interstitials off for good on that device: Settings → *Reset purchases (dev)* (non-release builds, only after a purchase) clears `ads_removed` and `iap_*`. iOS sandbox purchase sheets show a placeholder icon and "UNRATED" until a build is uploaded and an age rating is set; that's App Store Connect, not the app.

### Pilot Career (Ranks & XP)

10 realistic civil-aviation ranks (`kRanks` in `rank_service.dart`): Student → Private → Commercial Pilot → Second Officer → First Officer → Senior First Officer → Captain → Senior Captain → Training Captain → Chief Pilot (+ prestige ★ every 3000 XP). XP is awarded in `_onGoalReached`: first clear 60×tier, new stars 30×tier each, clean flight +15, PB +20, daily 150 + streak, achievements +100; tier = 1 + 0.5×world index. Runs that earn nothing new share a 300 XP/day cap. Ranks grant a currency multiplier on payouts, a one-off promotion bonus, and unlock rank-locked cosmetics (`CosmeticItem.rankRequired`). Insignia (wings / epaulette bars) is drawn by `paintInsignia` in `components/rank_insignia.dart`. The win result is exposed as `NarrowHaulGame.lastRunReward`. Lifetime stats: `ProgressService.getStat(stat*)`.

**Contracts** (`contracts_service.dart`, unlocked at Commercial Pilot): 3 daily tasks generated deterministically from the date (only feasible ones: unlocked worlds, stars left, daily not done), stored per day in `contracts_<date>` so they don't reshuffle; progress applied in `_onGoalReached` via `ContractsService.recordDelivery`, completed contracts + all-done bonus appear as XP lines. **Achievement toast:** `AchievementService.unlock(id, announce: true)` pushes to `AchievementService.announced`, shown by `_AchievementToastHost` (use only for mid-flight unlocks; win-time unlocks are listed on the level-complete screen). Mid-flight unlocks pay their XP with the delivery, or immediately on crash.

### Camera

Base zoom `_baseZoom = 28` (px/meter) on a reference phone 390 logical px tall; `_screenScale` (screen height ÷ 390, 0.8–3) multiplies it, so every screen (macOS window, iPad) shows the same height of cave and the ship and pod take the same share of it. Clamped to world bounds so the camera never shows outside the level. Auto-scales down if world fits inside viewport. Focus and zoom come from the pure `CameraDirector` (`lib/game/camera/camera_director.dart`, `test/camera_director_test.dart`); `_followCamera` only feeds it (velocity, tow + pod, local down, `probeAhead` gap to rock along the velocity) and clamps the result. The player picks a `CameraMode` (a `CameraProfile` each, `lib/game/ship/flight_tuning.dart`, `camera_mode`): Dynamic (default: 0.4 s lead, zooms out up to 10% with speed and 8% more when rock is < 1.5 s ahead, zooms in 12% when the player lets go of the controls for 0.8 s (`idleFor`, even while falling), sits still or creeps in to land, keeps a towed pod in view; zoom range 0.85–1.15), Look-ahead (lead + 12% tow zoom-out), Centred (the original, static) or Wide (15% further out). Zoom runs in log space, out fast (0.25 s), in slowly after a 0.6 s hold. **Safe frame:** `safeFrameNudge` shifts the view so the ship never sits under the dial, the THRUST/FIRE/rail cluster (`HudTouchControls.controlZones`) or the top-left gauges; to do that near the floor or walls the view may look `kCameraOverscroll` (6 m, 3 m at the top) past the world, so the rock is drawn that far out (`CaveTerrain.buildRockPath`, `WorldFrame` on TMX levels) and Flame's `setBounds` allows it (`test/camera_safe_frame_test.dart`). **Close-ups** (`CloseUp`, × the flight zoom): a level opens at 2.2× on the ship (2.6× on a new ship's first flight, never the Kestrel; 1.5× on retry), framed at 72% of the screen height, holds through the level card and eases out over 3 · 2 · 1 to GO; any input releases it in 0.45 s (onboarding levels without a countdown hold until the first input). A delivery pushes in 1.5× on ship and pod before the result screen (the camera keeps running while `RunState.won`). Off in Centred mode, demos and store captures (`test/camera_close_up_test.dart`). Shake is a `TraumaShake` offset added after the follow (crash, blasts, meltdown floor); reduced motion halves zoom swings and cuts shake. Rationale and tuning table: `docs/CAMERA.md`.

### Performance probe

`--dart-define=PERF=true` turns on `PerfMonitor` (`lib/game/perf/`, off = const-folded away). It tracks engine frame timings (UI build and raster), `update` and `render` per frame, game-logic laps (`PerfMonitor.lap`), load time and startup marks, and prints one `PERF <level> <outcome> …` line per flight, with an FPS readout in the corner. There are two benches:
- `test/autopilot/perf_bench_test.dart` (headless, every level, `build/perf_report.md`).
- `integration_test/perf_flight_test.dart`: demo replays with real rendering, run with `flutter drive --profile` and `--driver=test_driver/perf_driver.dart`; writes `build/perf_device_<level>.json`.

Numbers and the open GPU items are in `docs/PERF_BASELINE.md`. Measure before optimising: on the CPU the game is cheap (update p95 < 1 ms), so the open questions are raster cost on a phone.

**Test helpers** (`test/helpers/`): `caves.dart` (`allCaveDefs`, `shipOfCave`, `prebuildAllCaves` for a cave-heavy file's `setUpAll`: each test file is its own isolate with an empty cave cache), `levels.dart` (`levelIndexOf`, `caveLevelWhere`), `pump.dart` (`advance`, `freshSave`). `GameHarness` (`test/autopilot/harness.dart`) boots the real game (`boot(prefs:)`), `step(frames)`, and keeps built caves across loads (`debugKeepCaveCache`; debug builds otherwise `forgetCave` the loaded level for hot reload). `ProgressService.clock` fixes "today" for streak/daily tests.
